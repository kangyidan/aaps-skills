# 04 · 设置向导、配置构建器与 Profile 五参数

> 本章覆盖首次启动的设置向导、配置构建器（Config Builder）、首选项（Preferences），以及最关键的 Profile 五个参数（BR/ISF/IC/DIA/目标）的调校逻辑。

## 4.1 设置向导（Setup Wizard）

- 首次启动 AAPS 自动运行，一次性引导完成基础配置（权限、泵、CGM、Profile）。
- 目的：避免遗漏关键步骤（尤其权限对 AAPS 至关重要）。
- 运行期间 AAPS 可能"看起来没变化"——功能由**目标**逐步解锁，你是主人。
- 不理解/不同意 EULA 就不要用 AAPS。
- 结束即进入**目标 1**。
- 若中途退出，可重启向导或手动配置。

## 4.2 配置构建器（Config Builder）

按模块启停功能（泵、APS 算法、灵敏度检测、NSClient、自动化等）。要点：

- **泵**：选正确型号（与真实泵匹配）；无驱动/未完成早期目标时用**虚拟泵**。
- **APS 算法**：选 OpenAPS **SMB**（推荐，最新），或 OpenAPS AMA（旧，不推荐）。SMB 在目标 9 前保持禁用。
- **灵敏度检测**：Oref1（推荐，支持 UAM+SMB）/ WeightedAverage。目标 8 前仅作信息显示，不自动调输送。
- **Nightscout / NSClient**：URL 必须以 `/api/v1/` 结尾；上传器统一用 v1 或 v3（勿混用）。
- **自动化（Automation）**：目标 10 解锁。

## 4.3 首选项（Preferences）要点

- **主密码**：设置后才能导出（加密）；务必备份。
- **应用保护**：大剂量/设置更改/AAPS 本身可加密码或生物识别。
- **快速向导按钮**：按时间段显示标准餐食按钮（如早餐/午餐），定义碳水与时间窗；IOB 足够时自动隐藏。
- **默认临时目标（TT）**：预设值——
  - 即将进食（Eating Soon）：72 mg/dL / 4.0 mmol/l，45 分钟
  - 活动（Activity）：140 mg/dL / 7.8 mmol/l，90 分钟
  - 低血糖（Hypo）：125 mg/dL / 6.9 mmol/l，45 分钟
- **图表高低标记**：仅可视化（如 70–180 mg/dl / 3.9–10 mmol/l），非目标范围。
- **状态指示灯**：管路/胰岛素/传感器/电池/储药器寿命超阈值变黄→红。
- **最大允许大剂量 / 最大允许碳水量**：安全上限，设为合理值（≈一餐或一次校正所需）。
- **SMB 相关**：min_5m_carbimpact（SMB 默认 8，AMA 默认 5）。
- **NSClient v3**：所有上传器须用 v3；多数上传器尚不兼容，故由 AAPS 统一上传，禁用其他上传器。
- **自动设置导出**：启用后主密码本地保存≤4 周，到期需手动刷新。

## 4.4 Profile 五参数（系统运行基础）

Profile 是一组定义 AAPS 如何按血糖输注胰岛素的参数。**随着目标解锁可改更多参数，但底层 Profile 决定一切。**

| 参数 | 含义 |
|------|------|
| **BR（基础率）** | 背景胰岛素，单位 U/h，可逐小时不同 |
| **ISF（胰岛素敏感系数）** | 1 单位胰岛素降低多少血糖（mg/dl 或 mmol/l） |
| **IC / I:C（碳水系数）** | 1 单位胰岛素覆盖多少克碳水 |
| **DIA（胰岛素作用时长）** | 胰岛素在体内持续作用小时数（默认≥5h，常设 5–9h） |
| **目标（Target）** | AAPS 计算用的目标血糖范围（非你"努力维持"的范围） |

> 建议调校顺序：**先 BR → 再 ISF → 再 IC**（多数教育者与患者共识）。一次只改一个、小步调整、改后激活新 Profile、定期导出备份。

### 4.4.1 基础率 BR

- 准确 BR：醒来在范围内、可跳过/推迟餐食不升不降。
- BR 过高 → 低血糖；过低 → 高血糖。
- AAPS 以默认 BR 为"基线"；BR 过高会让"零临时基础率"过度减 IOB → 后续纠正过量 → 低血糖。
- 调整方法：无碳水基础率测试；或观察夜间 IOB（IOB 为负=BR 过高，反之为低）；变化应在 rise/drop 前 1–2 小时（因胰岛素类型而异）实施。

### 4.4.2 胰岛素敏感系数 ISF

- mg/dl：ISF=40 ⇒ 1 U 降约 40 mg/dl（140→100）。
- mmol/l：ISF=1.5 ⇒ 1 U 降约 1.5 mmol/l（8→6.5）。
- **ISF 值越小 = 越"强/激进"**（每单位降更多糖→闭环更激进、易低）；值越大 = 越"弱"（易高）。
- 起点估算（1700 规则）：`ISF ≈ 1700(mg/dl) 或 94(mmol/l) / TDD`（每日总剂量）。例 TDD=40U ⇒ ISF≈43 mg/dl / 2.4 mmol/l。
- 测试：暂停循环、IOB 归零、达稳定高血糖，按 1/ISF 估算注射，验证回落至目标。
- ISF 过低（过激进）→"过山车"式血糖，应调高 ISF 让纠正更温和。

### 4.4.3 碳水系数 IC / I:C

- 1:10 ⇒ 每 10g 碳水需 1U；25g 餐 ⇒ 2.5U。
- IC 值越小 = 越"强"（每单位覆盖更少碳水→更多胰岛素）；值越大 = 越"弱"（易高）。
- 欧洲"面包单位 BU"（12g 碳水）对应：`IC = 12g / BU因子`。例 2.4 U/BU ⇒ IC=5.0 g/U。
- 测试：IOB 零、血糖在范围、吃已知碳水、按 IC 估算注射，验证吸收后回落。

### 4.4.4 DIA

- 闭环中长尾效应重要（递归计算累积微小量）。
- 默认若未指定则 5h；部分方案（Lyumjev/Fiasp/NovoRapid/Humalog）建议 9h。
- Free-Peak Oref 可自定义峰值时间（高级，仅专家）。

### 4.4.5 目标（Target）

- AAPS 所有计算基于它：预测 BG 将出范围则行动。
- 可定义范围（最低 4/72，最高 10/180 用于 Profile；TT 最低 4/72，最高 15/225）。
- 目标过宽（如 ≥3 mmol/l）→ AAPS 很少动作（常无需调）。
- 夜间可设高些防低；晨间可设低些积累餐前 IOB。

## 4.5 报告/远程服务器

- **Nightscout**：目标 1 必需。启用全量上传（除非 BG 源就是 NS）。NSClient URL 以 `/api/v1/` 结尾。
- **Tidepool**：仅报告，不要额外上传器（会重复）。
- 详见 `chapters/02`、`09`。
